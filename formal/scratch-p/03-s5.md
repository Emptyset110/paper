## 5. Atomic Signatures and the Characteristic Suite

### 5.1 Windows, occurrences, decisions, and lift

For each rule $r$, the *window* $W_r(\gamma, n)$ is the tuple of fields the Table-1 row reads and writes, together with its *combination frame*: the index sets of its finite-map operations and the order data of its order-sensitive operators (iterator position; accumulator order). The normalization $\kappa_r$ maps a window to a finite multiset of *occurrences*: one scalar occurrence, one per-key occurrence per key of each pointwise index set, one witness occurrence per satisfied existential (conflict key, reliance edge, child edge), one per-item occurrence per accumulator entry. Crucially, $\kappa_r$ keeps equality *patterns* and forgets identities and counts: a registry of a thousand independent fibers contributes nothing to a rule that does not read them (framing), and a dependency set of any size contributes only the set of satisfaction *classes* present. We now fix this shape precisely; Appendix C instantiates it per rule.

**Definition 5 (window).** For $r \in \mathrm{Rules}$ and a state $\gamma$ with acting fiber $n$ (for O-Insert: acting data $(n,\pi,(d,p,e))$), the *window* $W_r(\gamma,n)$ is the tuple of exactly the abstract fields the Table-1 row's premises read and its writes touch, together with the row's *combination frame*: the index sets of its finite-map operations (the key set $d_n$ for the target product; the domain of the existential folds), and the *order data* of its order-sensitive operators (the iterator position; the accumulator's composition order as a finite list). Appendix C inventories $W_r$ per rule against the row.

**Definition 6 (occurrences; $\kappa_r$).** For each $r$, Appendix D supplies a finite alphabet $\Sigma_r$ of *occurrences*; the proofs use exactly these properties of it: **(D-A)** $\Sigma_r$ is finite and its occurrence classes cover exactly the guard atoms and write inputs of Table 1's row for $r$, at the granularity of Appendix D's tables — each occurrence records: (1) the truth values of the row's primitive scalar guard atoms; (2) the step constructor selected, if any; (3) the equality pattern among the finitely many names, keys, values, and tags read by that atomic decision; (4) witness/counterexample status of each existential or universal map condition; and (5) the normalized abstract update expected on one representative key, edge, or accumulator item. The map

$$\kappa_r : W_r \to \mathcal M_{\mathrm{fin}}(\Sigma_r)$$

sends a window to the multiset containing: one *scalar occurrence* (the row's scalar-atom valuation, step constructor, and scalar equality pattern); one *per-key occurrence* for each key in each pointwise index set of the frame; one *witness occurrence* for each element of each existential domain that satisfies the witness predicate (conflict key, child edge, reliance edge); and one *per-item occurrence* for each accumulator item. $\kappa_r$ forgets the frame's order data and the concrete identities (it keeps only equality patterns); the frame keeps them. Appendix C spells $\kappa_r$ out per rule.

**Definition 7 (decisions).** For each $r$, the per-occurrence decision codomain is

$$\mathrm{Decision}_r := \{\mathsf{block}(\varrho)\}_{\varrho} \;\uplus\; \{\mathsf{pass}\} \times \widehat U_r \times \widehat E_r^{\,*},$$

where $\varrho$ ranges over the finitely many refusal reasons of the row (one per premise schema), $\widehat U_r$ is the finite set of normalized per-occurrence update constructors of the row (enumerated per rule in Appendix C: e.g. for L-Begin, $\mathsf{commit}(k\text{-pattern} \mapsto \text{provider-pattern})$ and the state write $\theta_n \mapsto \mathsf{Reloading}(e_n,\mathrm{id}_\Gamma,\cdot)$; for L-Unload, $\mathsf{apply\mbox{-}inverse}(c)$ for each inverse class $c$ and the state write $\theta_n \mapsto \mathsf{Inactive}(\zeta)$), and $\widehat E_r$ the finite set of per-occurrence event constructors (with payload given by the occurrence's equality pattern). A *table* is a function $f_r : \Sigma_r \to \mathrm{Decision}_r$. $f_r^{\mathbb S}$ is the specification table read off Table 1's row (constructed rule-by-rule in Appendix C); $f_r^{\mathbb I}$ is the implementation table postulated by CF3.

**Definition 8 (lift).** $\mathrm{lift}_r$ takes the window $W$ (with its frame) and a $\mathrm{Decision}_r$-valued family indexed by $\kappa_r(W)$'s occurrences, and produces the rule-level result:

1. *(Enablement.)* The row's guard formula, a fixed monotone Boolean combination: the conjunction of the scalar occurrence's required atoms, the conjunction over all per-key occurrences of "this occurrence's decision is $\mathsf{pass}$", and, for each existential schema, presence (for positive premises) or absence (for negative premises, i.e. O-Insert's disjointness, O-Remove's childlessness, L-Unload's $\neg\mathrm{relied}$) of a witness occurrence. If the formula is false the rule-level result is the refusal $\mathsf{block}(\varrho)$ of the leftmost failing premise (orchestration rules) resp. non-applicability (lifecycle rules).
2. *(Update.)* The row's $\mathrm{edit} \circ \Psi$ assembled from the per-occurrence updates: field assignments from the scalar occurrence's update; the finite-map product $\bigsqcup_k$ of per-key updates over the frame's index set (well-defined and order-irrelevant because per-key supports are disjoint singletons); the removal/extension of a registry entry; and, for the order-sensitive operators, the composition of per-item updates *in the frame's order data* (the iterator's $g \circ h$; the accumulator's LIFO application).
3. *(Emission.)* The concatenation of the per-occurrence emissions in the frame's order (a single landing's events; the accumulator's $\mathsf{inv}$ events in composition order followed by $\mathsf{deact}$).

These are exactly the finite-map unions, restrictions, existential folds, and accumulator composition operators of [SZC26]; no other operator appears in Appendix C.

**Remark 1 (where the order lives).** $\kappa_r(W)$ is a multiset and carries no order; the accumulator's composition order and the iterator's position are frame data of $W$, consumed by $\mathrm{lift}_r$. Consequently CF3 constrains the implementation's *per-occurrence* behavior through $f_r^{\mathbb I}$ and its *combination* behavior through the requirement that it use the specified $\mathrm{lift}_r$ — two separate obligations. The Transport Lemma (§6.2) is stated with exactly this split; a version claiming that $\kappa$-equal windows receive identical *whole-rule* results would be false for windows that agree as multisets but differ in accumulator order. (This corrected an earlier draft of the theory in which order data was homeless.)

**Guards factor through the support.** For later reuse we record: clause 1 of Definition 8 depends on the family only through *which occurrence classes are present*, i.e. through $\mathrm{supp}(\kappa_r(W))$ and the per-class decisions — conjunctions and presence/absence tests are insensitive to multiplicities. This is the signature-level face of "no rule reads a cardinality" and is used in Appendix C's per-row checks and in §6.2.

### 5.2 Normalization invariance, equivariance, and framing

Three facts about $\kappa_r$ and $\mathbb S$ are consumed throughout §6; we prove them here, once.

**Lemma 1 ($\kappa$ is invariant under renaming and $\simeq/\approx$).** Let $r \in \mathrm{Rules}$, let $\chi$ be a sort-preserving bijection, and let $\gamma, \gamma'$ be states with $\gamma' \simeq \chi\cdot\gamma$ (eq. 53's reading of $\simeq$). Then for every $n$, $W_r(\gamma', \chi_{\mathfrak N}(n))$ and $W_r(\gamma,n)$ have equal images under $\kappa_r$:

$$\kappa_r\big(W_r(\gamma',\chi_{\mathfrak N}(n))\big) = \kappa_r\big(W_r(\gamma,n)\big),$$

and the two frames correspond under $\chi$ (same index-set images, same order data up to $\chi$).

*Proof.* We verify the claim for each of the five kinds of data an occurrence records (Definition 6, items 1–5), quantifying over all occurrences of the window.

(1) *Scalar guard atoms.* By the premise inventory in the proof of Lemma 55 of [SZC26], every premise of every rule is of one of four kinds: a pattern match on $\theta_n$ or $\tau_n$; the component conditions of O-Insert; a condition mentioning $\mathrm{target}_n$ or $\mathrm{relied}_n$ (reading $\tau$, committed views inside the $\theta$'s, and $\mathrm{dom}(\sigma_m)$'s); or a read of $\mathrm{dom}(F_\gamma)$. A pattern match on a constructor is preserved by $\chi$ (constructors are reserved) and by $\simeq$ (eq. 53 keeps every control field up to $\simeq$ on its type, and $\theta$'s constructor is compared by equality). Membership and equality conditions on names/keys are preserved by bijections and read identically at $\simeq$-related states because $\simeq$ (eq. 53) demands agreement of $\mathrm{dom}(F)$ and of every control field. $\mathrm{target}$ and $\mathrm{relied}$ are functions of exactly those fields plus $\mathrm{dom}(\sigma_\gamma)$, and Definition 33 relates coeffect contexts only where their domains agree; so each scalar atom has the same truth value at the two windows. Hence the scalar occurrences are equal (their recorded valuations coincide, and their recorded equality patterns coincide because a bijection preserves every equality and every inequality among the finitely many read identities — this is the defining property of an *equality pattern*).

(2) *Step constructors.* The iterator constituent of $\theta_n$ is compared by $\simeq$ as Definition 51 compares iterators: componentwise, $\mathsf{Nothing}$ with $\mathsf{Nothing}$, $\mathsf{Just}$ with $\mathsf{Just}$, and for the test-component language of Definition 2 the step at the head is a data constructor preserved on the nose by $\chi$ (payloads renamed sortwise). So the recorded constructor is equal.

(3) *Equality patterns.* As in (1): bijections preserve equality patterns by definition; $\simeq$-variation of values is quotiented by the normalization $\kappa$ performs (occurrences record value *classes*, and Definitions 33/24 make $\simeq_k$-related values fall in the same class — this is what "normalized" means in Definition 6).

(4) *Witness status.* Each existential domain (conflict keys, child edges, reliance edges, satisfaction providers) is carried bijectively by $\chi$ onto the corresponding domain at $\chi\cdot\gamma$ (the domains are defined by equalities and memberships among carried fields), and $\simeq$ preserves each witness predicate by (1). Hence witness occurrences correspond one-to-one — equality *as multisets*, since the correspondence is a bijection of index sets.

(5) *Normalized per-item updates.* The expected update on a representative item is a constructor of $\widehat U_r$ with payload an equality pattern; by (1)–(4) these agree.

Finally, the frames: the index sets are carried bijectively by $\chi_K$/$\chi_{\mathfrak N}$, and the order data (iterator position, accumulator list order) are structural constituents of $\theta_n$ preserved by $\simeq$'s componentwise iterator comparison and untouched by renaming. $\square$

**Corollary 1 (reachable signatures are $\simeq/\chi$-stable).** If $\gamma$ is reachable in $\mathbb S$ and $s \in \kappa_r(W_r(\gamma,n))$, and $\gamma' \simeq \chi\cdot\gamma$ is also reachable, then the same $s$ lies in $\kappa_r(W_r(\gamma',\chi n))$. In particular the predicate "$s$ is exhibited at some reachable state" is well-defined on the quotient the calculus descends to (Lemma 55), and Appendix D's reachability analysis **(D-B)** — $s \in \Sigma_r^{\mathrm{reach}}$ iff some finite $\mathbb S$-derivation from the empty registry reaches a pointed window whose $\kappa_r$-image contains $s$ — is invariant under the renamings of Lemma 56. $\square$

Lemma 56 of [SZC26] is equivariance under name bijections $\chi : \mathfrak N \to \mathfrak N$ alone. CF2 demands equivariance under all four sorts. We prove the extension once; Appendix C cites it per rule.

**Lemma 2 (equivariance in all four sorts).** Let $\chi$ be a sort-preserving bijection. Then $\chi\cdot\gamma$ is a state, well formed where $\gamma$ is, and $\mathrm{step}^t = r(n)$ carries $\gamma^t$ to $\gamma^{t+1}$ iff $r(\chi_{\mathfrak N}(n))$ carries $\chi\cdot\gamma^t$ to $\chi\cdot\gamma^{t+1}$, with the emitted events and certificate carried to their $\chi$-images.

*Proof.* The name part is Lemma 56 verbatim. For keys, values, and tags we run Lemma 56's proof scheme over the remaining reads and writes, using the same premise inventory as in Lemma 1(1):

*Keys.* A premise reads a key only through: membership $k \in d_n$, $k \in p$, $k \in p_m$, $k \in \mathrm{dom}(\sigma_m)$ (inside $\gamma \vDash d_n$ and $\mathrm{provider}_k$); emptiness of the intersection $p \cap p_m$ (O-Insert); equality of two committed/target views on their common domain $d_n$ (the $\mathrm{target}_n(\gamma) = \omega$ / $\neq \omega$ premises), which unfolds to per-key equalities of *names*; and the key parameter of an operation step (Defs. 23/29/31: $k \in \mathrm{dom}(\sigma)$, $\rho(k) \in \mathrm{dom}(\sigma)$, $k \in \mathrm{dom}(\rho)$). Each is a membership or equality, preserved by the bijection $\chi_K$ (with $\rho$, $\iota$ reindexed alongside). The writes touching keys are finite-map updates at named keys ($\sigma[k \mapsto v]$, $\sigma \smallsetminus k$, $\rho[k \mapsto r]$, $\iota[k \mapsto \iota(k) \oplus_k \nu]$, $\omega$'s domain $d_n$), all commuting with reindexing by $\chi_K$. No rule or operation computes a key, orders two keys, or reads $|{\cdot}|$ of a key set.

*Values.* No premise of any Table-1 row inspects a value: values occur only inside $\sigma$-tables and iterator payloads, and the only value-consuming positions are the operations' arguments and results (Defs. 23/24/29/31, Alg. 6), which pass values through or compare them by the coeffect's own $\simeq_k$ — an equivalence that the sort bijection is required to respect on classes (reserved value classes fixed; cf. §2.1's notation). Writes place values into tables pointwise. So value bijections commute with every premise and write.

*Tags.* Tags occur only as the payload of $\mathsf{track}$/$\mathsf{app}$/$\mathsf{inv}$ and are never compared by any premise; they are carried through the accumulator as opaque payloads. Renaming commutes trivially.

Events and certificates: each event letter's payload is a tuple of carried identities, written from the same reads the premises make, so the emission at $\chi\cdot\gamma$ is the $\chi$-image; the certificate's $(\widehat s, \widehat a)$ is $\kappa$-normalized and hence *fixed* by $\chi$ (Lemma 1) — the certificate stream is $\chi$-invariant, which is what lets canonical experiments compare it across renamings. Well-formedness (Def. 58) is four conditions comparing names with names and keys with keys, preserved as in Lemma 56. $\square$

**Lemma 3 (frame).** Let $r$ apply at $\gamma$ acting on $n$, and let $\gamma^+$ extend $\gamma$ by fibers and keys wholly outside $W_r(\gamma,n)$ in the following precise sense: every added fiber $m$ is vestigial (Lemma 57's sense: $\tau_m = \top$, $\theta_m = \mathsf{Inactive}(\bot)$, $\sigma_m = \varnothing$, no $\pi_{m'} = m$) or is a fiber none of whose fields occur in $W_r(\gamma,n)$'s reads — no key of $p_m$ or $\mathrm{dom}(\sigma_m)$ meets the row's key reads, $m$ is not a parent/child/reliance witness read by the row, and $m$'s activity does not change $\mathrm{target}_n$ — and every added key lies outside the row's key reads. Then $r$ applies at $\gamma^+$ acting on $n$ with the same $\kappa_r$-image, the same per-occurrence decisions under $f_r^{\mathbb S}$, and a result differing from $r$'s result at $\gamma$ exactly by the added material.

*Proof.* For vestigial additions this is Lemma 57(1) (a vestigial $n$ contributes to no observation a premise of a rule acting on $m \neq n$ reads: it is not Active so it enters no $\sigma_\gamma$; it provides no key, leaving $\gamma \vDash d_m$ and $\mathrm{target}_m$ unmoved; $\mathrm{installed}$ fails so it contributes no disjunct to $\mathrm{relied}_m$; it names no $\pi$; and $\theta,\tau,\pi$ are read only by rules acting on it), together with Lemma 54(1): no step acting on $n$ writes a table of $m \neq n$, so the addition survives untouched. For non-vestigial additions satisfying the stated separations, re-run Lemma 57's proof clause by clause: each premise of $r$'s row reads only the window fields (that is Definition 5, checked per rule in Appendix C), and by hypothesis the added material meets none of them; the only two premises that relax rather than restrict under *removal* — O-Insert's freshness and disjointness (Lemma 57(2)) — here run in the extension direction and are excluded by the hypothesis that added fibers claim no key the row reads and are not the inserted name. The writes are confined to $n$ (Def. 48, via Lemma 54), so they commute with the extension. $\kappa_r$-equality is then Lemma 1 with $\chi = \mathrm{id}$ restricted along the window agreement. $\square$

### 5.4 Canonical experiments and $T^\star$

For each rule $r$ and reachable signature $s$, the canonical experiment $(\rho_{r,s}, V_{r,s})$ drives the system, by an explicit orchestration script over explicit component data, to a pointed configuration realizing $s$, lets the attempt at $r$ occur (directly for orchestration rules; by settling for lifecycle rules), and asserts $\equiv$-equality of the implementation's outcome set with the specification's at that point — certificates included. Then

$$T^\star = \{(\rho_{r,s}, V_{r,s}) \mid r \in \mathrm{Rules} \cup \mathrm{Ops},\ s \in \Sigma_r^{\mathrm{reach}}\}, \qquad |T^\star| = 60 \text{ scripts}.$$

A single script may realize several occurrences at once, which is why $|T^\star| < 86$. Some scripts are load-bearing in nontrivial ways: realizing the *installed-only-provided* satisfaction class requires observing a begin attempt inside another fiber's guarded teardown window (Appendix D, S-Beg-5); realizing the inactive-access error under Algorithm 6 requires five components and five settles (S-It-4). The properties of the scripts that the proofs consume — the attempt-point construction, exhaustive outcome computation, attempt-point determinacy, and schedule-invariant distinguishing subwords for order-sensitive aspects — are the numbered obligations **(D-C)**, **(D-E)**, **(D-F)**, **(D-G)** of Appendix D.17. The 32-test obligation suite that predates this construction (§8) is *material* for $T^\star$: the explorer track (§7) audits which signatures it covers, and the audit — not intuition — decides whether it must grow.
